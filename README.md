## 🌟 Ignition : The First Step

To begin your journey, you need not be a grand archmage of programming. You simply need a **curious mind** and the **desire to create**.

1.  **Prerequisites:** Ensure you have a modern web browser (Chrome, Firefox, Safari, Edge) and a text editor you are comfortable with. Familiarity with JavaScript is helpful, but the included templates are designed to be approachable.
2.  **The Invocation:** Visit the main repository page on GitHub and select the "Fork" option at the top right. This creates a personal sandbox for you to practice without affecting the primary timeline.
3.  **Your Sanctum:** Once forked, rename your copy to something personal, like `my-arcane-workshop`. This is your space.

## 🔧 Installation & Binding the Ritual

For a developer, "installation" is akin to preparing your ritual circle. Here is how to set the boundaries of your workspace.

- **Data Transfer:** Utilize GitHub's "Download ZIP" feature to obtain a snapshot of the codebase. Alternatively, use your preferred Git GUI client to clone the repository to your local machine.
- **Dependency Management:** This project utilizes a modern, package-agnostic approach. You will find a `manifest` file at the root directory. Run the standard resolution command for your chosen language (e.g., `deno task install` or `bun install`). The system will procure all necessary components.
- **Environment Configuration:** Create a local `.env` file (or copy from `.env.example`). Here, you will define your personal "resonance frequency"—any API keys or internal settings. The core system runs on a **zero-configuration** baseline, but this file allows for deep personalization.

## 🤝 Contributing: Joining the Circle

We are a school, and every student is also a teacher. Your contributions are the lifeblood of this project. We welcome bug fixes, new spells, documentation updates, and UI enhancements.

**The Golden Rule of Contribution:**
1.  **Seek the Issue:** Before you start crafting, check the "Open Issues" tab to ensure you are not duplicating work.
2.  **Create a New Branch:** Never work directly on the `main` branch. Create a descriptive branch name like `feat/add-vision-sigil`.
3.  **Practice the Craft:** Follow the existing style and patterns you see in the code. Write clear, succinct comments.
4.  **Submit a Pull Request (PR):** Describe what you have changed and why. Link it to the Issue you resolved. A mentor will review your work, offering feedback just like a master reviewing a student's thesis.
